# 设计:纸页库与归档目录脱离 note.md 的 vault

日期:2026-11-20。状态:草案,待用户认可。认可后按 AGENTS.md 第 1 条先改规范与契约,再改实现。

归属标注:**[用户定]** 是用户在 2026-11-20 对话里拍板的;**[我的判断]** 是设计者的判断,用户可推翻。

## 1. 意图

用户希望玄霜写作在桌面上不再受 note.md 的 vault 设置左右 **[用户定]**:

- 稿子归档到哪个本地目录,由玄霜写作自己设置,可以是任意目录,不必在 vault 里 **[用户定]**;
- 纸页库也与 vault 脱钩:每台电脑只有一套玄霜写作纸页,打开哪个 vault、甚至不打开 vault,写的都是同一套 **[用户定]**(“连库一起脱钩”)。

桌面仍是 note.md 插件,不做独立桌面应用,ADR 0008 不变 **[用户定]**(方案 A)。五期顺序不变 **[用户定]**(“按规划的节奏来做”)。

## 3. 目标、非目标、反目标

目标:

- 桌面上每台机器一个**写作工作区**:一套纸页库、一份输入日志、一组同步凭据,与 vault 无关 **[用户定]**。
- 不开 vault 也能打开玄霜写作并写字、同步 **[用户定]**。
- 归档目录是本机设置,可选任意本地目录;投影文件直接放在该目录里(不再套 `inbox/writings/`) **[我的判断]**。
- 已有用户升级后不丢页、不重新配对:现有那套库原样接管 **[用户定]**。

非目标:

- 不做独立桌面应用,不迁原生编辑桥。
- 不改纸页模型、文件名规则(`YYYY-MM-DD-NN.writing.md` 与同名 `.meta.json`)、便携文件格式、线格式、同步协议。
- 不新增常驻的目录监视;外部修改仍在现有两个时机观察。
- 不处理 iOS(iOS 本来就没有投影,只受内核接口改名影响)。
- 不合并多个旧纸页库。

反目标(技术上能跑也算失败):

- 升级后看不到原来的纸页,或被要求重新配对。
- 改归档目录时删掉或搬动用户旧目录里的文件 **[用户定]**。
- 覆盖任何可能含用户外部改动的文件。
- 归档目录不可用(移动硬盘拔掉、卷没挂载、权限变了)时打不开会话、影响写字或丢正文。正文以纸页库为准,投影只是派生物(ADR 0009)。
- 卷没挂载时在内置盘上建出同名“影子目录”并把投影写进去。
- 在 note.md 与 sumiwrite 两边各留一份可编辑的投影逻辑。

## 4. 方案

对话里比较过的两种(用户选 A):

- **A. 仍是 note.md 插件,纸页库与归档目录由玄霜写作自己管(选定)**。改内核路径计算、宿主工作区定位、后台 `open` 参数与契约,加一项设置。不动五期顺序,代价是桌面仍需安装 note.md。
- **B. 现在就做独立桌面应用**。等于推翻 ADR 0008、提前第 5 期,要迁原生编辑桥、重做窗口签名更新与 Linux 打包,并排到 iOS 之前。放弃:超出“不依赖 vault 设置”所需,且打乱用户刚定的节奏。

脱钩范围也比较过两种(用户选前者):

- **连库一起脱钩(选定)**。
- **只改归档目录**:改动小,但切 vault 仍切纸页,只做到一半。放弃。

## 5. 设计

### 5.1 写作工作区

- 桌面每台机器一个工作区,由一个**工作区 ID** 标识(不透明字符串)。纸页库路径为 `<app_data>/sumi/<工作区 ID>/documents.sqlite3`,输入日志同目录;钥匙串 `profile` 就用工作区 ID **[我的判断]**。
- 工作区 ID 与归档目录存在宿主的本机配置文件 `<app_data>/sumi/workspace.json`(`{"schema":1,"workspace":"<ID>","archive":"<绝对路径>"|null}`) **[我的判断]**。放在纸页库外面,是因为打开库之前就要知道库在哪。`archive` 为 `null` 表示尚未设置。
- 打开玄霜写作不再要求已打开 vault;切换或关闭 vault 不再停止编辑会话。`current` 与 `current_native` 两道 vault 检查都改为“工作区 ID 一致”;`Workspace.selected_root` 删掉。
- 后台 `open` 的 `vault` 参数改为 `archive`(绝对路径,可为 `null`),另加 `workspace`(工作区 ID);`open` **不再要求归档目录存在**。“同一 vault 只许绑一个会话”改为“同一工作区只许绑一个会话”。回调里的 `root` 改为工作区 ID。服务协议 `VERSION` 升到 2 **[我的判断]**。
- 作者署名改为取归档目录的 git config(`human_actor_for_vault(Some(归档目录))`:目录在 git 仓库里就用仓库配置,否则落到全局 git config 与系统用户名);归档目录未设置或不可用时传 `None`,只用系统用户名 **[我的判断]**。理由:署名跟着稿子落盘的地方走,不跟着恰好开着的 vault 走。
- `home-content-edit` 事件只在归档目录位于当前打开的 vault 内时发出,路径按该 vault 相对路径算;否则不发 **[我的判断]**。

### 5.2 首次升级的接管

升级后第一次打开玄霜写作,宿主若没有 `workspace.json` **[我的判断]**:

1. 列出 `<app_data>/sumi/` 下的哈希目录(排除 `fonts/`)。
2. 选一个接管:
   - 恰好一个:接管它。
   - 多于一个:当前开着 vault 且 `sha256(canonicalize(当前 vault 根))` 命中其一,接管那个;否则接管纸页库修改时间最新的那个。
   - 其余目录原样留在磁盘上,不删,在设置里列出“未接管的旧纸页库”,只作提示。
   - 一个都没有(新装):新生成一个 UUID 作工作区 ID。
3. 接管就是把该目录名作为工作区 ID,原地使用,不搬文件。钥匙串 `profile` 是同一哈希,配对原样可用。
4. 归档目录初值:
   - 当前开着 vault,且它的哈希就是被接管的那个目录名:取 `<该 vault>/inbox/writings/`,与升级前一致。
   - 新装且开着 vault:取 `<当前 vault>/inbox/writings/`。
   - 其他情况(推算不出、或新装没开 vault):`archive` 记为 `null`,打开玄霜写作时提示“选择归档目录”。不自动落到某个默认目录,避免所有页在一个陌生目录里重写一遍 **[我的判断]**。未设置期间照常写字与同步,投影处于 `projection-pending`。
5. 原子写入 `workspace.json`。之后不再重复接管。

### 5.3 归档目录

**路径规则**(内核 `projection::paths(archive, filename)` 与 `publish(archive, …)`) **[我的判断]**:

- 投影文件直接放在归档目录里,不再拼 `inbox/writings`。
- 归档目录本身必须已经存在且是目录;它本身是符号链接时接受,先 canonicalize(与现行“vault 根可以是链接”一致,iCloud、Dropbox 的软链目录照常可用)。
- 运行时**不自动创建归档目录本身**。不存在或不可访问即视为“归档目录不可用”,投影进入 `projection-pending` 并按现行节奏重试,正文照常保存。这样卷没挂载时不会在内置盘上建影子目录。
- 归档目录只在用户用选择器设定、或接管时取 `<vault>/inbox/writings/` 而它不存在时,由宿主创建一次;创建时沿用“新建的各层不得是符号链接或非目录”的检查。

**改目录** **[我的判断]**:

- 走“停会话、改配置、重开”,复用现有的停止屏障(桌面附录 §5.5 / 01 §5.5),不新增服务消息。
  1. 宿主用自己的目录选择框选新目录(插件 WebView 弹不出系统选择框)。
  2. 对整个工作区执行现行的停止屏障:排空持久队列、尝试最终投影。最终投影**不要求成功**:旧目录不可用恰恰是最想换目录的时候,所以旧目录写不进去也允许切换。
  3. 清空投影队列与各页的投影基线(新目录与旧目录的基线没有关系;未完成的旧作业作废,正文已在纸页库里)。
  4. 写 `workspace.json`,用新 `archive` 重开后台会话。
  5. 后台按页在新目录发布,规则见下一条。
- 旧目录里的文件原样保留,不删不搬 **[用户定]**。
- 不再要求“没有冲突页才能切换”:旧目录里的冲突原样留在旧目录,三份文本已按现行规则保全。

**无基线首写**(新目录、或接管后基线为空时,每页一次) **[我的判断]**:

内核新增一个“无基线首写”入口,按目标位置同名文件的情况处理:

| 目标位置 | 处理 |
|---|---|
| 没有同名文件 | 直接写入,记为新基线 |
| 有同名文件,且与本次待写内容逐字节相同 | 不写,记为基线 |
| 有同名文件对,且能确认是**本页自己写下的旧版本**:sidecar 的 `page_id`、`write_epoch` 与本页一致,且正文哈希、行数、行 ID 序列与 sidecar 自洽(即没被外部改过,规则同桌面附录 §2.3) | 覆盖。旧版本的内容都在 CRDT 历史里,不会丢。这覆盖了“A 换到 B 再换回 A”的情形 |
| 其他(属于别的页、身份不符、正文被外部改过、只有半对文件) | 不覆盖,这一页的投影标为冲突,走现行“恢复”入口处理;其余页照常发布 |

**“把便携文件恢复成新纸页”** **[我的判断]**:

- 读取范围从“vault 根内”改为“当前归档目录内,或当前打开的 vault 内”,两者其一即可。`Evidence.vault` / `verify_vault` 改为记录并校验这个“允许根”。
- `recovery.rs:225` 写死的 `inbox/writings` 改为当前归档目录。
- 入口:归档目录在 vault 内时,文件树入口照旧;另外在玄霜写作自己的“恢复”界面加一项“从归档目录选文件恢复”,用宿主的文件选择框,起点为归档目录。

**其他**:

- `open_path` 只认归档目录里的文件。归档目录在 vault 外时,文件树里看不到这些文件,这个入口自然用不到。
- 归档目录在 vault 里时,宿主文件树的成对规则(契约 03 §3、桌面附录 §2.5)与 OKF 写入规矩照旧适用;在 vault 外时不涉及。
- 设置只在本机生效,不同步 **[用户定]**。

### 5.4 契约与发版

这是跨边界改动:宿主 `src-tauri/src/sumi/`、`sotvault` 与 `okf` 的耦合归 note.md。先改 `docs/handoff/03-notemd-contract.md`,`host-contract` 从 v1 升到 v2 **[我的判断]**。v2 清单:

- 后台 `open`:`vault` → `archive`(可空)、新增 `workspace`;服务协议 `VERSION` 1 → 2。
- 回调 `root` 语义改为工作区 ID。
- `sumi_page_path` 返回值:`vault_root` → `archive`。
- 新增宿主命令:`host.sumi.archive_get`(返回当前归档目录、是否可用、未接管的旧库列表)、`host.sumi.archive_choose`(宿主弹目录选择框并执行 5.3 的改目录流程)、`host.sumi.recovery_choose`(宿主弹文件选择框,起点为归档目录)。命令名由执行者在契约里定稿。
- 打开玄霜写作的授权门不再要求先开 vault;manifest 的 `vault.read`、`vault.write` 能力是否还需要,由契约改写时核对(归档目录在 vault 内时仍会写 vault)。
- §3 投影约定:目录一行改为“归档目录”。

宿主与插件配套发版(契约 §4)。

### 5.6 排期

作为**第 2 期详细计划里的一个独立任务**,排在插件壳迁入 sumiwrite 之后,这样插件后台的改动直接落在本仓库 **[用户定]**(“按推荐”)。宿主侧改动在 note.md,受其 `CLAUDE.md` 约束(CHANGELOG 门禁)。内核改动发新 tag(`core-v0.2.0`),`paths`/`publish` 参数语义变了,是破坏性变更。

### 5.7 验证

- 内核:`paths` 覆盖任意目录、归档目录本身是链接时接受、归档目录不存在时报不可用而不创建;无基线首写的四种情况各一条测试。
- 宿主:接管的各种情况(一个;多个且当前 vault 命中;多个且不命中;新装开着 vault;新装没开 vault)各一条测试;不开 vault 能打开工作区;切 vault 不停会话;署名取归档目录的 git config;恢复只接受允许根内的文件;`lifecycle_tests.rs`、`recovery_tests.rs` 全过。
- 后台:改目录后各页在新目录发布,旧目录文件字节不变;旧目录不可用时仍能切换;A→B→A 时 A 里本页的旧版本被覆盖、被外部改过的文件不被覆盖;归档目录不可用时 `open` 成功、写字正常、投影为 pending,恢复可用后补上。
- 手工:本机升级后纸页、配对状态都在;把归档目录改到 vault 外,写字、关闭、重开、强杀后正文与投影都正确;拔掉放归档目录的移动硬盘再写字,不丢字、不建影子目录。

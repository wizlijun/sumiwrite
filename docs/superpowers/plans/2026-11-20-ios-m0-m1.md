# iOS M0/M1 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 `apps/ios/` 建正式的 iOS 应用:`core/` 经 UniFFI 编成 XCFramework 并在模拟器上通过夹具比对(M0),再做一页纸的富文本编辑面,每次上屏都经内核成为一次事务并存进内核的 SQLite 库(M1)。用户用一条命令把它签名装到自己的 iPhone 上。

**Architecture:** Rust crate `sumi-ios-ffi` 包住 `write-core`,只做类型转换和加锁,导出 `CorePage`(文档 + 当前 `SourceMap`)与 `CoreStore`(库)两个对象。Swift 分三层:`Core/` 是可单测的模型层,负责差异计算、编辑结果、保存队列和光标锚点;`Appearance/` 与 `Sound/` 放纯逻辑与资源;`Editor/` 是 UIKit 编辑面和 SwiftUI 外壳。XcodeGen 生成工程,构建产物都放在 git 忽略的 `apps/ios/build/`。

**Tech Stack:** Rust 1.99.0(`write-core` 0.2.0、`uniffi =0.32.2`)、Swift 5、UIKit + TextKit 2、SwiftUI、AVAudioEngine、XCTest、XcodeGen 2.46、Xcode 27.2、bash。

**Spec:** `docs/superpowers/specs/2026-11-20-ios-m0-m1-design.md`(下称“设计”)。现行规范是 `docs/spec/platform/ios.md` 与 `docs/spec/04-editing-experience.md`;任务 1 先改规范。

## Global Constraints

- 代码全部放在 `apps/ios/`;生成的 `.xcodeproj`、`apps/ios/build/`、`apps/ios/ffi/target/`、`apps/ios/Signing.local.xcconfig` 都不进仓库。
- 仓库里不得出现 Bundle ID、团队 ID、签名身份、设备 UDID(AGENTS.md 第 5 条)。`Base.xcconfig` 里的 `PRODUCT_BUNDLE_IDENTIFIER = local.sumiwrite.placeholder` 只是模拟器用的占位值,真值由 git 忽略的 `Signing.local.xcconfig` 覆盖。
- 红线:Swift 里不得出现 CRDT、行时间、合并或恢复逻辑。Swift 只做可见文本的差异计算、类型转换和界面;Markdown 事务、撤销、规范化都由内核完成。
- Rust 一律 `export PATH="$HOME/.cargo/bin:$PATH"` 后用 `cargo +1.99.0`;iOS 目标只有 `aarch64-apple-ios` 与 `aarch64-apple-ios-sim`;构建时 `IPHONEOS_DEPLOYMENT_TARGET=17.0`。
- UniFFI 版本 `=0.32.2`,只用过程宏,不写 UDL。crate 名 `sumi-ios-ffi`,库名 `sumi_ios_ffi`,XCFramework 名 `SumiCoreFFI.xcframework`。
- 应用最低系统 iOS 17.0,`TARGETED_DEVICE_FAMILY = "1,2"`,显示名 `玄霜写作`,`MARKETING_VERSION = 0.1.0`。
- 模拟器测试目的地 `platform=iOS Simulator,name=${SIM:-iPhone 17 Pro Max}`。agent 只跑模拟器,不签名、不装真机、不读钥匙串或凭据。
- 外观默认值与范围按 04「排版默认值」:字号 22(8–96)、行距 1.6(1–3)、主题 `dim`、光标动态 `breathing`、聚焦打字开。打字音默认开,音色 `typewriter`。
- 六种主题色值(前景 / 背景)按 04「主题」原样:`ink` `#ffffff`/`#000000`;`dim` `#b8b8b8`/`#111111`;`paper` `#111111`/`#ffffff`;`sepia` `#44413c`/`#f3ead7`;`crt` `#0ccc68`/`#000000`;`crt-blue` `#7fb4ff`/`#000000`。选区背景是前景色的 22% 透明度。
- 光标:宽度为字号 / 11,限制在 2–3 pt;高度取字体 ascender 到 descender;`breathing` 每 4 秒一轮(2 秒渐暗、2 秒渐亮),最低不透明度 0.25;连续输入不重启相位。
- 界面文案(中文,原样):保存失败时状态条显示 `保存失败`;库打不开时显示 `打不开纸页`。
- 文档用简体中文;提交信息用英文祈使句,结尾 `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`。提交前跑 `bash docs/check.sh`,必须输出 `OK`;改了 `core/` 的提交还要跑 `core/README.md`「Verification」段的前两条命令。
- 只在本地分支 `ios-m0-m1`(worktree `/Users/bruce/git/sumiwrite-ios`)上提交;推送、合并要先得到用户同意。

## Review Focus

1. **内核拒绝一次编辑**,比如在受保护的代码块里改字,或者修订过期。编辑面应该回到内核的正文,不能和内核分叉;光标留在拒绝前的位置附近。测试:任务 4 `test_editInsideProtectedBlockIsRejectedAndReset`、`test_staleRevisionIsRejectedAndReset`。
2. **组字中途**(拼音未上屏),编辑面的文字变了。这时不调内核、不发事务;上屏后只发一次事务。测试:任务 4 `test_composingTextIsNeverSubmitted`。
3. **退到后台时,队列里还有没写完的增量**。检查点应排在这些增量之后,并且成功;如果检查点发现修订对不上(此时用户又打了字),只跳过这次检查点,不算保存失败。测试:任务 5 `test_checkpointRunsAfterQueuedDeltas`、`test_staleCheckpointIsSkippedNotFailure`。
4. **库文件损坏或打不开**。不能悄悄新建一页把旧库盖掉,而是只读显示 `打不开纸页`,库文件原封不动。测试:任务 5 `test_corruptStoreIsLeftUntouchedAndReadOnly`。
5. **存下的光标锚点失效**,比如库被换过、页不同或数据损坏。光标退到文末,不崩溃。测试:任务 5 `test_foreignOrGarbageAnchorFallsBackToEnd`。

# 平台附录 · iOS/iPadOS 版

玄霜写作(Sumi Write)的 iOS/iPadOS 版是一个独立的原生应用,不依赖 note.md,也没有 vault。**本附录全部是计划**:写的时候还没有任何 iOS 代码,也没有任何 iOS 发布。下文每一条都标 `[计划:iOS]` 或 `[未定]`,不能当作已存在的行为引用。

- **来源**:设计文档 `docs/superpowers/specs/2026-11-18-sumiwrite-extraction-design.md` §2、§4.3、§4.4、§5.4、§8、§10、§12(note.md 仓库 `docs/sumiwrite-extraction` 分支,提交 `0c11629f`;该分支尚未推送到任何远端,暂不公开,见 [04-known-gaps §2.2](../../handoff/04-known-gaps.md))。旧主规范 `2026-11-07-immersive-write-design.md` 中涉及移动端的条目也已对照。
- **归属标记**:**[用户定]** 是用户亲自拍板的;**[我的判断]** 是设计者的判断,用户可以推翻。两者均沿用设计文档原文。
- **共用规则**:iOS 与桌面共用纸页、Markdown 与行时间、同步、编辑体验、字体的规则,分别见 [01](../01-pages-and-storage.md)、[02](../02-markdown-and-line-time.md)、[03](../03-sync.md)、[04](../04-editing-experience.md)、[05](../05-fonts.md)。本附录只写 iOS 独有的部分。
- **技术选型**:[ADR 0010](../../adr/0010-ios-uikit-textkit2-uniffi.md)(UIKit + TextKit 2 + UniFFI)、[ADR 0011](../../adr/0011-ios-personal-use-identity-layer.md)(先自用,身份层分开)、[ADR 0012](../../adr/0012-shared-session-module.md)(共用会话模块 `session/`)、[ADR 0009](../../adr/0009-page-store-vs-vault-projection.md)(纸页存储与 vault 投影分开)。

**定位**:

- 第一阶段**先自用** **[用户定]**:走 TestFlight 或自签名安装,沿用现有的配对码,账号体系不动。
- 第一阶段**不公开发行** **[用户定]**:没有注册登录、多租户、付费,也不上 App Store。
- 技术栈是 **Swift 原生界面 + Rust 内核** **[用户定]**(设计 §4.4)。Tauri Mobile 这类跨平台壳已排除,因为它不是原生界面,输入法和键盘避让都做不好。
- 具体分层是界面用 UIKit/TextKit 2 加 SwiftUI,经 UniFFI 调用 Rust 内核 **[我的判断]**。这一层出自设计 §10.2 的架构图,设计没有给它标注归属,不属于 §4.4 的用户决定。
- 最低系统 **iOS 17 / iPadOS 17** **[我的判断]**。理由:TextKit 2 在这个版本上已足够稳定,自用场景也不需要照顾旧设备。

## 1. 范围

### 做

状态:[计划:iOS]

第一阶段做以下这些:

- **一页纸写作**:打开应用即恢复上次的纸页、光标和阅读位置。
- **纸页管理**:纸页概览、新建、上一页、下一页、移到废纸篓、从废纸篓恢复。
- **外观**:六种主题、字号、行距。六组字体按需下载,规则与桌面相同(见 [05-fonts](../05-fonts.md))。
- **光标**:自绘竖线光标,可选呼吸或常亮。
- **输入**:系统输入法正常组字、选词。正文避让软键盘;接上硬件键盘后收回留白。
- **快捷键**:iPad 硬件键盘支持快捷键,按规范中的语义映射。
- **同步**:离线可写,联网后自动合并;可以和桌面同时编辑同一页。
- **配对**:粘贴桌面端生成的邀请文本、填写同步服务地址,即加入同步空间。凭据存在钥匙串里。
- **导出**:当前纸页导出为 Markdown,走系统分享。

### 不做

状态:[计划:iOS]

以下各项第一阶段明确不做。除注明外,均为 **[我的判断]**(设计 §10.1):

- vault、文件夹、文件名。
- 打字音效,留到后续。
- 自定义输入法或键盘扩展。
- 专注窗口的固定尺寸规格。这在手机上没有意义;iPad 直接用系统的多窗口与全屏。
- 注册登录、付费、上架 **[用户定]**。设计 §2 把“iOS 第一阶段不做公开发行:没有注册登录、多租户、付费、App Store 上架”定为用户决定;设计 §10.1 的不做清单虽把它列在 [我的判断] 之下,以 §2 为准。
- 扫码配对。桌面端现在只输出邀请文本,没有二维码;要加二维码就得改桌面插件,所以留到后续。

## 2. 架构

### 2.1 四层结构

状态:[计划:iOS]

```
SwiftUI 外壳(纸页概览、设置、配对)
        │
UIKit 编辑面(UITextView + TextKit 2,自绘光标)
        │  编辑事务(修订号 + 可见 UTF-16 范围)
Swift 薄适配层(把 UIKit 回调转成会话调用,钥匙串读写)
        │  UniFFI
Rust:session(单一编辑 owner、组字期间暂缓远端更新、本机输入日志、
            崩溃恢复、同步协调与同步客户端)
      core(文档、SourceMap、存储、候选会话)
```

| 层 | 职责 | 不做什么 |
|---|---|---|
| SwiftUI 外壳 | 纸页概览、设置、配对界面 | 不碰正文,不碰 CRDT |
| UIKit 编辑面 | `UITextView` + TextKit 2 排版。自绘光标,压住系统光标。处理系统输入法组字、选区和键盘避让;把用户输入整理成编辑事务 | 不解析 Markdown,不写文件,不连网络 |
| Swift 薄适配层 | 把 UIKit 回调转成 `session` 调用,读写钥匙串 | 不含会话或同步逻辑 |
| Rust `session` | 单一编辑 owner;组字期间暂缓远端更新;本机输入日志;崩溃恢复;同步协调与同步客户端 | 不依赖 Tauri 和插件 SDK(第 3 期的完成标志) |
| Rust `core` | 文档、SourceMap、存储、候选会话;生成最小的规范 Markdown 事务 | — |

- **内核构建**:内核编成 XCFramework,由 UniFFI 生成 Swift 接口。
- **会话与同步逻辑不在 Swift 里重写** **[我的判断]**。这些逻辑目前分在两处:宿主的 `src-tauri/src/sumi/`(owner、组字防护、输入日志、恢复,约 8.7k 行),以及插件后台的 `sync.rs`、`coordinator.rs`、`durability.rs`(约 6k 行)。它们决定了数据不丢、合并正确,测试也最重。在 Swift 里再写一遍,就违反了“iOS 与桌面的 CRDT 或行时间实现不得分叉”这一反目标。所以第 3 期先把其中与宿主无关的部分下沉为 `session/`,iOS 直接用它(见 [ADR 0012](../../adr/0012-shared-session-module.md))。
- **线程**:持久化在后台线程做,输入线程不等锁。
- **证书校验**:插件后台的 WebSocket 用的是 `tokio-tungstenite` 的 `rustls-tls-native-roots` 特性(`plugins-src/write/backend/Cargo.toml`)。这套根证书加载方式在 iOS 上很可能不能用(**未实测**),所以下沉到 `session/` 时要换一种证书校验方式。这条已作为后果记进 [ADR 0010](../../adr/0010-ios-uikit-textkit2-uniffi.md)。

### 2.2 编辑事务的形状

状态:[计划:iOS]

- 编辑事务的形状与桌面原生编辑桥一致。原生回调带上修订号和可见文本的 UTF-16 范围,由内核生成最小的规范 Markdown 事务。桌面一侧的现行定义见[契约 §1.2 表 B](../../handoff/03-notemd-contract.md):`Edit` 是相对 `base_revision` 的 UTF-16 替换。
- 组字中的文字**不进 CRDT**。组字期间到达的远端更新先暂存,组字结束后再应用。这是内核 README 的既有规定,iOS 照做。
- 撤销与重做交给 CRDT 的撤销 owner,不用 UIKit 自带的撤销栈。这一条是按桌面现行做法类推的(桌面关闭了 AppKit 撤销),尚未单独确认。[未定]
- 一次事务被接受之前,必须先写进本机输入日志,和桌面“先记日志、再接受修订”的顺序一样。日志写失败时编辑面如何呈现(桌面的做法是 `draft_error`,保留可见文字但禁止继续修改),由 M2 定。[未定]

### 2.3 存储位置与钥匙串

状态:[计划:iOS]

- **纸页存储**:内核的 SQLite 保存完整的 CRDT 历史,是本机事实源,放在应用沙盒里(设计 §5.4)。iOS **没有 vault 投影**,不生成 `inbox/writings/` 目录,也不生成 `.writing.md` 文件(见 [ADR 0009](../../adr/0009-page-store-vs-vault-projection.md))。
- **钥匙串**:空间、设备凭据存在 iOS 钥匙串里,由 Swift 薄适配层读写。凭据不进纸页数据库、偏好或日志。
- **发行事务**:Bundle ID、签名身份、TestFlight 配置都不进仓库,仓库里只放凭据引用(设计 §12)。

以下待定:

- 钥匙串的服务名与访问组 [未定]。桌面 macOS 的服务名是 `com.notemd.sumi.credentials.v1`,iOS 是否沿用,由 M3 定。
- 沙盒内的具体目录 [未定]。旧主规范写的是“应用私有 Documents 内的 Markdown 快照与持久状态”;设计 §5.4 只写了“SQLite 放在应用沙盒里”。是否另存一份 Markdown 快照、放在 Documents 还是 Application Support,由 M2 定。

## 3. 交互

### 3.1 配对流程

状态:[计划:iOS]

1. 在桌面玄霜写作里生成一次性配对码(邀请文本)。邀请含 256 位密钥,5 分钟后过期(源仓库 `write-sync-worker/src/protocol.ts`:`invitationSeconds: 300`,密钥为 32 字节随机数)。
2. 邀请文本不适合手输,靠通用剪贴板或隔空投送传到手机上。
3. 在 iOS 的配对界面**粘贴邀请文本**,并**填写同步服务地址**。
4. 加入同步空间,凭据存入钥匙串。

- 配对界面**不出现管理员密钥**(见 5.1)。
- 邀请里的空间 ID 必须与目标服务返回的身份一致,服务地址的来源也必须一致,否则拒绝。这是桌面插件后台的现行校验(`plugins-src/write/backend/src/network.rs`),iOS 照做。
- 服务地址能否从邀请文本中自动带出:[未定]。现行邀请只含空间 ID、配对码和过期时间,不含服务地址。

### 3.2 键盘避让与硬件键盘

状态:[计划:iOS]

- 正文跟随系统软键盘的实际 inset 避让,用 `keyboardLayoutGuide` 跟踪。接上硬件键盘、软键盘收起后,收回底部留白。光标始终留在可用编辑区内,不被留白挡住。
- 键盘外观只能通过 `keyboardAppearance` 给系统有限的提示,不能保证与主题同色。
- iPad 硬件键盘的快捷键按 [04-editing-experience](../04-editing-experience.md) 的语义映射,不照搬 macOS 的物理键位。M4 的验收标准是快捷键表逐项通过。
- 组字期间,快捷键先归系统输入法。
- 具体键位表 [未定],由 M4 定。它要与系统和 UIKit 的保留键(如 ⌘Tab、地球键)避开冲突。

### 3.3 导出

状态:[计划:iOS]

- 当前纸页导出为 Markdown,走系统分享面板。
- 导出的文件名与 frontmatter 是否沿用桌面投影格式 [未定]。旧主规范还提到“保留行时间的迁移需要配对快照打包”,这一项不在第一阶段范围内。

## 6. 前置条件

### 6.1 第 3 期完成

状态:[计划:iOS]

iOS 是第 4 期,开工的前提是第 3 期已经完成:

- 实时编辑会话与同步协调中**与宿主无关**的部分,已经下沉到 `session/`;

`session/` 具体怎么切分,由第 3 期的计划定。迁移分期见 [`02-migration-plan.md`](../../handoff/02-migration-plan.md)。

## 7. 工程待答问题

本节收集 iOS 实现前必须回答、但设计与本附录都还没有答案的工程问题。每一项都 [未定],由对应里程碑的计划给出答案;答案定下后写回上文对应小节。

### 7.1 UniFFI 接口形状

状态:[未定]

- `session/` 经 UniFFI 暴露的接口用同步调用还是异步调用;回调(远端更新、持久事件)在哪个线程上回到 Swift;错误怎样映射成 Swift 的错误类型。由 M0 定。

### 7.2 异步运行时、后台与数据保护

状态:[未定]

- 内核与会话在 iOS 上用哪种异步运行时、由谁持有其生命周期。
- 应用被挂起或锁屏时 WebSocket 连接怎样处理,回到前台怎样重连。
- 纸页 SQLite 文件用哪一档 Data Protection 等级;锁屏后仍需写入时,与输入日志的落盘要求是否冲突。由 M2、M3 定。

### 7.3 iPad 多场景与单一编辑 owner

状态:[未定]

- iPad 上多个窗口场景打开同一页时,怎样与“同一页只有一个编辑 owner”的规则相容(拒绝、只读,还是转交 owner)。桌面现行规则见 [notemd-desktop §3.1](notemd-desktop.md)。由 M4 定。

### 7.4 字体注册与下载策略

状态:[未定]

- 下载后的字体用 CTFontManager 注册在哪个作用域(进程内还是更大范围)。
- 七个字体文件合计约 93.9 MB(见 [05-fonts](../05-fonts.md)),蜂窝网络下是否允许下载、本机存储吃紧时怎样处理,尚无策略。

### 7.5 落盘保证

状态:[未定]

- 桌面 macOS 依靠 SQLite 的 `synchronous=FULL` 与 `fullfsync`(见 [notemd-desktop §8.1](notemd-desktop.md))。iOS/APFS 上是否同样设置、`F_FULLFSYNC` 的实际效果,都没有设计,也没有测试。由 M2 定。

### 7.6 互操作夹具的路径

状态:[未定]

- M0 要在 Swift 侧加载现有的互操作夹具。第 1 期把 `write-core` 改名为 `core/` 后,夹具路径是 `core/tests/fixtures/yrs-v1.json`;iOS 测试怎样引用它(复制、链接还是构建时生成),由 M0 定。

### 7.7 XCFramework 目标与工具链

状态:[未定]

- XCFramework 至少包含真机 arm64 与模拟器 arm64 两个目标;是否还要模拟器 x86_64,未定。
- Rust 工具链要与桌面一致,钉在 1.99(见 [02-migration-plan](../../handoff/02-migration-plan.md) 第 1 期);iOS 目标怎样随同钉住,由 M0 定。

### 7.8 撤销归属

状态:[未定]

- 撤销交给 CRDT 撤销 owner 时,UITextView 自带的撤销栈怎样关闭或接管(见 §2.2)。由 M1 定。

### 7.9 内存预算

状态:[未定]

- 同步协议允许客户端一次完整回放最多 65 MB(见 [03-sync](../03-sync.md));这在 iPhone 上的内存预算是否可接受、要不要分段回放,未评估。由 M3 定。

### 7.10 VoiceOver 与自绘光标

状态:[未定]

- 自绘光标时,VoiceOver 怎样获得插入点与选区位置;系统光标隐藏后,无障碍行为不能退化。由 M1 定。

### 7.11 Bundle ID 与钥匙串访问组

状态:[未定]

- 已列在 §2.3(钥匙串服务名与访问组)与 §6.2(Bundle ID),此处不重复。

# 0008 独立单一仓库;桌面先留作 note.md 插件,原生编辑桥归宿主

类型:新
状态:已决定(第 0 期);代码迁移按设计 §8 分期执行。
记录日期:2026-11-18;出处为抽离设计 §4.1、§4.2、§5、§8、§9、§12。归属标注沿用设计原文:**[用户定]** 是用户明确选择的,**[我的判断]** 是设计者补全、用户可推翻的。

## 背景

玄霜写作已有自己的内核、服务契约、同步服务和品牌,下一步要做 iOS/iPadOS 原生版。继续放在 note.md 里,两个产品的边界、发版节奏和文档会混在一起(设计 §1)。但桌面版深度依赖宿主:原生编辑桥编进宿主、实时编辑会话在宿主 `src-tauri/src/sumi/`、宿主直接依赖 `write-core` 与 `sumi-protocol`,插件壳又依赖 note.md 的插件 SDK、文案与快捷键模块、签名公证流程(设计 §3)。

## 决定

- **新建独立仓库 `sumiwrite`,一个仓库装下产品本身**:内核、服务契约、同步服务、共用会话模块、桌面插件壳、iOS 应用与全部规范(设计 §1、§2、§6;“单一仓库”这一点设计未标注归属)。仓库公开 **[用户定]**;许可证统一 Apache-2.0 **[我的判断]**(设计 §12)。
- **桌面先仍是 note.md 插件,桌面独立应用写进路线图,iOS 上线后按 §9 评估** **[用户定]**(设计 §4.1)。
- **原生编辑桥 `tauri-plugin-native-editor` 归 note.md,不迁**:它是宿主能力(设计 §5.2)。宿主内的 Sumi 界面与 Tauri 适配、插件 SDK、市场、签名与发版、历史发布证据也留在 note.md。
- **文档先行,代码分期迁** **[用户定]**:本轮 note.md 零改动;第 1 期迁内核、服务契约、同步服务,第 2 期迁插件壳与资源,第 3 期下沉会话,第 4 期 iOS,第 5 期评估桌面独立(设计 §4.2、§8)。每期可单独验证和回退。
- **迁移保留 git 历史**:在 note.md 的全新克隆上用 `git filter-repo` 按路径提取并入;note.md 同期删除对应目录并改依赖,不留副本 **[我的判断]**(设计 §8)。
- **两仓之间是成文、带版本的契约 `host-contract v1`**:依赖双向按固定 tag 引用,crate 层面不成环 **[我的判断]**;签名、公证、上架留在 note.md,sumiwrite 产出待签构建物 **[我的判断]**(设计 §5.3;[03-notemd-contract.md](../handoff/03-notemd-contract.md))。

## 放弃的方案

设计 §4.1、§4.2 记录的:

- **桌面也立即做独立应用**:边界最干净,但要重做窗口、签名、更新、Linux 打包,拖慢 iOS。
- **一步到位迁全部代码**:没有过渡期,但构建、发版、市场打包同时改,出问题难以归因。
- **不带历史的快照复制**:已排除——两份源码必然分叉,正是反目标“两个仓库各留一份可编辑的源码”(设计 §2)。

## 后果

得到的:

- 产品边界、规范和发版节奏归一处;iOS 从第一天起就在产品仓库里,与桌面共用内核。
- 桌面不用重新验收;note.md 每一期都能照常构建和发版(设计 §2 反目标)。

付出的:

- **原生桥改动仍受宿主发版牵制**:改控件行为、布局、光标、IME 交接或原生接口,仍要重建、签名、公证、发布 note.md 宿主(主规范 §8.1;[0005](0005-native-text-controls.md))。sumiwrite 拥有产品规则,却不拥有桌面上执行这些规则的最关键代码。
- **跨仓协调成本**:契约版本一变,两边要配套发版;本地联调要用 `[patch]` 指向本地目录;共享快捷键 TypeScript 的处理方式到第 2 期才定(设计 §5.3)。
- **迁移期两仓都在动**:第 1–3 期每期都要改 note.md 的依赖与构建,note.md 的 CHANGELOG 门禁与 OKF 写入规矩继续约束宿主侧改动(设计 §3)。
- 历史证据只能链接到 note.md 的宿主 tag、提交号与报告路径,插件自己没有 tag。
- **再评估标准(设计 §9)**:第 5 期满足下列任意两条即启动桌面独立,届时原生编辑桥随之迁入 sumiwrite,note.md 改为只识别和阅读 `.writing.md`:
  1. 过去一个季度里,因原生编辑桥改动而被迫配套发宿主的次数,明显多于宿主自身需要的发版;
  2. iOS 版证明内核加原生界面的组合可以脱离宿主运行,且维护成本可接受;
  3. 出现不使用 note.md 但想用玄霜写作的桌面用户需求。

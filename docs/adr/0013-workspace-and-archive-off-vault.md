# 0013 纸页库与归档目录脱离 vault

类型:新
状态:已决定(2026-11-20);实现排在第 2 期详细计划的一个独立任务,配套发版(`host-contract v2`)前尚未交付。
记录日期:2026-11-20;出处为[归档目录设计](../superpowers/specs/2026-11-20-archive-directory-design.md)。归属标注沿用设计原文:**[用户定]** 是用户明确选择的,**[我的判断]** 是设计者补全、用户可推翻的。

## 背景

桌面版的纸页库与投影目录都挂在 note.md 当前打开的 vault 上:

- 投影写死在 `<vault>/inbox/writings/`。
- 纸页库按 vault 根的哈希分库,输入日志与钥匙串里的同步凭据也按同一哈希分。
- 没开 vault 就打不开玄霜写作;切 vault 就切走一整套纸页。

用户希望稿子归档到哪个本地目录由玄霜写作自己设置,可以是任意目录;并且连库一起脱钩:每台电脑只有一套纸页,打开哪个 vault、甚至不开 vault,写的都是同一套 **[用户定]**。桌面仍是 note.md 插件,ADR 0008 不变 **[用户定]**。

## 决定

- **每台机器一个写作工作区**:一个不透明的工作区 ID 对应一套纸页库、一份输入日志、一组同步凭据,路径为 `<app_data>/sumi/<工作区 ID>/`,钥匙串 `profile` 用工作区 ID **[用户定]**(设计 §5.1)。工作区 ID 与归档目录记在宿主本机配置 `<app_data>/sumi/workspace.json`,放在纸页库外面,因为打开库之前就要知道库在哪 **[我的判断]**。
- **打开玄霜写作不再要求已打开 vault**;切换或关闭 vault 不停止编辑会话。后台 `open` 的 `vault` 改为 `archive`(可空)并加 `workspace`,回调的 `root` 改为工作区 ID,服务协议 `VERSION` 升到 2 **[我的判断]**(设计 §5.1)。
- **首次升级原样接管现有那套库**:一个就接管它,多个按当前 vault 命中或修改时间最新选一个,其余留在磁盘上只作提示,不删不合并;钥匙串 `profile` 不变,不丢页、不重新配对 **[用户定]**。归档目录初值能由升级前的 vault 推算出来就沿用 `<vault>/inbox/writings/`,推算不出就记为未设置,提示用户选择 **[我的判断]**(设计 §5.2)。
- **归档目录是本机设置,可选任意本地目录**;投影文件直接放在其中,不再套 `inbox/writings/`;目录必须已存在、本身可为符号链接、运行时不创建,不可用时投影进入 `projection-pending` 而正文照常保存 **[我的判断]**(设计 §5.3)。
- **改归档目录**走“停会话、改配置、重开”,旧目录里的文件不删不搬 **[用户定]**;新目录里按页做“无基线首写”:没有同名文件就写,逐字节相同就记为基线,确认是本页自己的旧版本才覆盖,其他一律不覆盖并标为冲突 **[我的判断]**(设计 §5.3)。
- **契约升到 `host-contract v2`**,宿主与插件配套发版(设计 §5.4)。

## 放弃的方案

设计 §4 记录的:

- **方案 B:现在就做独立桌面应用**:放弃。等于推翻 [0008](0008-standalone-repo-desktop-stays-plugin.md)、提前第 5 期,要迁原生编辑桥、重做窗口签名更新与 Linux 打包,并排到 iOS 之前;超出“不依赖 vault 设置”所需,也打乱用户刚定的节奏。
- **只改归档目录**:放弃。改动小,但切 vault 仍切纸页,只做到一半。

## 后果

得到的:

- 玄霜写作的纸页、同步与配对不再受 vault 切换左右,不开 vault 也能写字。
- 稿子归档位置由用户自己定,可以在 vault 外。
- 归档目录不可用(移动硬盘拔掉、卷没挂载)时不影响写字、不丢正文,也不会在内置盘上建出影子目录。

付出的:

- ADR 0009 的“vault 投影”自此称“归档投影”。0009 的分层结论不变,只是名称与落点改了;`vault 投影` 列为退役名称,对照见 [`MAPPING.md`](../spec/MAPPING.md) 文末。
- **多个旧纸页库不合并**:首次升级只接管其中一个,其余留在磁盘上、在设置里列出提示。想要另一套里的纸页,目前没有合并入口。
- 这是跨边界的主版本升级:宿主 `src-tauri/src/sumi/`、`okf` 的耦合归 note.md,要先改 [`03-notemd-contract.md`](../handoff/03-notemd-contract.md),宿主与插件配套发版;内核发 `core-v0.2.0`,`paths`/`publish` 的参数语义变了,是破坏性变更。
- 工作区与归档目录的设置只在本机生效,不同步。
- 以上都尚未发布,规范对应小节标 `[未定]`,交付后补证据。

# apps/ios

iOS 应用(M0、M1)。与桌面共用同一套 Rust 内核 `core/`,经 `ffi/`(UniFFI)暴露给 Swift;Swift 里不含 CRDT、行时间、合并或恢复逻辑。设计见 [`docs/superpowers/specs/2026-11-20-ios-m0-m1-design.md`](../../docs/superpowers/specs/2026-11-20-ios-m0-m1-design.md)。

## 一次性准备

```
rustup +1.99.0 target add aarch64-apple-ios aarch64-apple-ios-sim
```

另需 Xcode 与 XcodeGen。

实体键盘的内嵌输入法(规范 [`ios.md` §3.6](../../docs/spec/platform/ios.md#36-实体键盘的内嵌输入法))来自本机的 Swift 包 RimeKit:放在 `~/git/rime-kit`(与本仓库同级;`project.yml` 用相对路径 `../../../rime-kit` 引用,GPL-3.0)。先在那里取一次 librime 二进制与雾凇词库:

```
bash ~/git/rime-kit/scripts/fetch.sh
```

`test-sim.sh` 与 `install-device.sh` 每次构建前都会再跑一次 `fetch.sh`(已取过就跳过);找不到 RimeKit 时打印「缺 RimeKit:见 apps/ios/README.md」并退出。

按住说话(规范 [`ios.md` §3.8](../../docs/spec/platform/ios.md#38-语音输入))来自本机的 Swift 包 VoiceKit(产品 `VoiceKit`、`VoiceKitUI`,从 rapp 移植):放在 `~/git/voice-kit`(与本仓库同级;`project.yml` 用相对路径 `../../../voice-kit` 引用)。它没有远端,也不用另取二进制,放好目录即可。语音的落地由 `VoiceLandingTests` 覆盖(组字先上屏、结果进内核、一次撤销撤掉;长按右 ⌥ 开始、Tab 插入原话、设置关掉时右 ⌥ 照常往下传);识别、权限、音频只靠真机。

## 构建

- `bash apps/ios/scripts/build-core.sh`:产出 `build/SumiCoreFFI.xcframework`、`build/gen/sumi_ios_ffi.swift` 和 `build/fixtures/`(`yrs-v1.json`、`yjs-v1.json`、`desktop.sqlite3`、`golden.json`)。可重复执行。
- `xcodegen generate`(在 `apps/ios/` 下):生成 `SumiWrite.xcodeproj`,该工程不入库;本地包 RimeKit(产品 `RimeKit`、`RimeKitUI`)随之接入。
- 真机:`bash apps/ios/scripts/install-device.sh <设备名或 UDID>`,需先配好签名。
- TestFlight:`bash apps/ios/scripts/upload-testflight.sh`,打包并上传到 App Store Connect,见「TestFlight」一节。

## Verification

```
bash apps/ios/scripts/test-sim.sh
cargo +1.99.0 test --manifest-path apps/ios/ffi/Cargo.toml
```

第一条先取 RimeKit 的二进制与词库(`fetch.sh`),再构建内核、生成工程并在模拟器(默认 iPhone 17 Pro Max,可用 `SIM` 覆盖)上跑 XCTest,必须以 `** TEST SUCCEEDED **` 结束。内嵌输入法的接线由 `RimeIntegrationTests` 用假的输入法覆盖(组字不进内核、上屏、切页前上屏、系统组字照旧拦切页、候选行位置与样式、点按候选与状态字菜单、空闲时候选行只剩状态字、打字音、切换中 / 英的快捷键随设置传入且不算打字、中英文自动空格、候选行与输入行的间距随行距、状态字渐隐);引擎本身的测试在 RimeKit 仓库里跑。

语音输入的 Sumi 一侧由 `VoiceLandingTests` 跑在上面的 XCTest 里;VoiceKit 本身的测试在它自己的目录跑(与本仓库同级,见「一次性准备」):`cd ../voice-kit && xcodebuild test -scheme VoiceKit-Package -destination 'platform=iOS Simulator,name=iPhone 17 Pro Max' -quiet`。

手工项(不进自动测试):性能测量,在真机上记录输入延迟与大页载入时间。

## 语音输入手工验收

规范 [`ios.md` §3.8](../../docs/spec/platform/ios.md#38-语音输入)。在真机上逐条执行;识别、权限、音频、本地网络询问模拟器测不了。本人 2026-11-24 在 iPhone Duo 真机验收通过(提交 50bf798)。

1. 按住麦克风时被系统手势或弹窗打断(下拉控制中心、本地网络询问):录音不丢,松手照常三选;
2. 实体键盘右 ⌥ 能单独送到(HID 键码),⌥ 与别的键组合(如 ⌥+空格)照常输入、不触发说话;
3. 来电时正在说话会取消(走系统音频打断);
4. 填了接入点后:设置里出现本地网络询问;长语音(超过 10 个字)出现整理卡、流式出字;插入后一次撤销回原话、再撤销全去掉;
5. 整理中按任意键:原话立即落地,按键照常处理;
6. 整理中把应用切到后台再回来:原话已在页里;整理中强杀应用,下次打开放回本页末尾并提示;
7. 按住麦克风说话,松手三选(插入、原话、取消)各走一遍,结果与规范一致;
8. 有 Rime 组字时按住说话:组字先按原文上屏,再开始录音;
9. 说话中接入 AirPods(音频路由变化):按取消处理,已说出的字不插入;
10. 在系统设置里拒绝语音识别或麦克风权限后按住说话:出现提示与「去设置」,点它能跳到设置;
11. 实体键盘说话:单独长按右 ⌥ 开始,松开插入,Esc 取消,Tab 插入原话;
12. 接入点空着时说长语音:不整理,直接插入原话;
13. 语音结束后继续打字,打字音仍响(音频会话已交还)。
14. 软键盘弹着时按住麦克风:开始录音时软键盘收起;松手插入后软键盘展开,光标在刚插入的字后面;取消时软键盘回来、正文不变;接实体键盘时说完不弹软键盘;
15. 连续说 1 分钟以上(iOS 26 以上):不被切断,到 5 分钟才按手指所在的选项松手。

## 真机安装

1. 复制签名模板:`cp apps/ios/Signing.example.xcconfig apps/ios/Signing.local.xcconfig`,在 `Signing.local.xcconfig` 里填自己的团队与 Bundle ID(详见下一节「签名」)。该文件被 git 忽略;没有它,安装脚本会直接退出。
2. 做过一次性准备(见上)。
3. 设备连上电脑并解锁,运行 `bash apps/ios/scripts/install-device.sh "<设备名>"`(设备名或 UDID 均可)。脚本依次构建内核、生成工程、用 `xcodebuild -configuration Release -allowProvisioningUpdates` 构建(Release 配置,输入延迟等手工测量按这个配置记),再用 `xcrun devicectl device install app` 装到设备。
4. 首次安装后,在设备的「设置 › 通用 › VPN 与设备管理」里信任开发者,然后才能打开应用。
5. 首次在某台设备上安装,还需要两件事:设备已开启开发者模式(「设置 › 隐私与安全性 › 开发者模式」,开启后需重启),并且设备已与这台 Mac 配对、信任这台 Mac。

## 内嵌输入法手工验收

在 iPad(接实体键盘,如妙控键盘)上逐条执行;模拟器测不了实体键盘、键盘扩展与真实的按键时序。对应规范 [`ios.md` §3.6](../../docs/spec/platform/ios.md#36-实体键盘的内嵌输入法)。

上机前可先在模拟器上过一遍:`bash apps/ios/scripts/sim-rime.sh [--no-build] [场景...]` 在专用模拟器(默认名 `sumi-rime-e2e`,没有就建)上打开实体键盘,用 RimeKit 的 `tools/sim/simkey` 发真实的 HID 按键,点按由 UI 测试 `SumiWriteUITests/TapServer` 代点,每步截图到 `build/sim-rime/<场景>/`;各场景每张截图的预期写在脚本开头,逐张对照判定。它只是测试工具,不进 Verification,也不代替下面的真机项。

1. 接实体键盘,系统输入源是简体拼音或英文时,在正文里打拼音都由内置输入法接管,不出现系统候选条;候选行在光标下一行出现,带主题底色,字体字号与正文一致。空闲(无组字、无候选)时只在右端剩状态字「中」那一小块底色,下一行其余的字露出来;点在那一行别处落到正文上(挪光标),点「中」字(含它下方一点)弹出菜单。
2. 组字在光标处带下划线;候选行盖住下一行,打字时不随光标横移,换行时跟着下移一行。
3. 空格、数字键选词;点 ‹ › 翻页;手指点候选上屏;上屏后正文与内核一致(划掉应用再打开仍在),光标在上屏文字之后。
4. 左 Shift 单按切中英,状态字「中 / 英」跟着变;英文时字母直接上屏,没有组字和候选。右 Shift 单按不切(雾凇 `default.yaml` 的 `ascii_composer/switch_key` 是 `Shift_L: commit_code`、`Shift_R: noop`;若用户期望右 Shift 也切,记下来)。左右 Shift 的按下与松开都要到 `pressesBegan` / `pressesEnded`(HID 0xE1 / 0xE5);妙控键盘若把单按 Shift 当作别的用途(例如系统的切换输入源)吞掉,记下来。组字中单按左 Shift:按原文上屏再切英文。按住 Shift 时点正文,松开不误切中英。
5. 按住退格、按住字母连发;快打长句不丢键;每次按键打字音只响一声,修饰键不响。
6. 点状态字弹出系统菜单「中文」「英文」「系统输入法」,当前项打勾。选「英文」:状态字变「英」,打 abc 直接上屏;选「中文」切回。选「系统输入法」:组字清掉(不上屏),按键全交给系统,状态字变「系」;再选「中文」或「英文」切回来,两边都对。划掉应用再打开,选了「系统输入法」的记录还在(中 / 英不记,重开是「中」)。
7. 拔掉实体键盘,只用软键盘:候选行消失,软键盘与系统输入法的行为与没有内嵌输入法时完全相同。
8. 内置输入法组字中按 ⌘[、⌘]、⌘N、⇧⌘L、⌘,,点菜单的 ‹ › 新建、总览、设置,或切到后台:组字按原文上屏进内核,不丢,再切换;选「系」用系统拼音组字时切页,照旧提示「请先完成输入」。组字中 ⌘= ⌘- ⌘0 不生效,Esc 交给输入法:聚焦打字中组字,按 Esc,组字清掉(不上屏),聚焦打字不退出,光标行不动(选区通知晚到时真机才看得出)。
9. 从正文中间续写:组字插在光标处、后文照常回流;候选行盖住下一行,聚焦打字时不被渐隐淡掉;光标在视区最后一行时正文先上滚一行,候选行留在视区里。
10. 组字中点正文别处、粘贴、⌘Z、从别的应用拖入文字都不响应;上屏后恢复。组字中再按 ⌘←、⌘→、⌥⌫、⌘⌫(键盘导航与删除键自动测试没有锁,看引擎是否接走;若穿过去改了文字或光标,记下来)。
11. 组字中拉下控制中心或切到别的应用:组字按原文上屏,不响打字音。保存失败(只读)后按字母键不进字、不出候选。
12. 长按连发后松开、或按住键时被取消(拉控制中心、切应用),再回来:打字音与聚焦打字照常(按住键与按键计数已复位)。
13. 没接实体键盘(只用软键盘)时,从别的应用把文字拖进正文,与没有内嵌输入法时一样可用。
14. 长页中间(上下都有大段会换行的文字)聚焦打字,连续上屏几次:每次上屏后候选行仍紧贴光标行的下一行,不上移盖住光标行或它上面的字(2026-11-20 真机反馈的跳动;在 af10879 的真机构建上已不复现)。
15. 打开一篇长页(几十段会换行的文字),光标放在文末,点状态字选「英文」连打几个单词、空格和回车;再选「中文」后单按左 Shift 切到英文,同样打一遍:每一键之后光标都在、看得到,文字不上下跳(只在进入聚焦打字和换行时平滑移一行),状态字小块不变高(2026-11-21 真机反馈「切到英文时光标丢失、上下跳动」)。
16. 状态字与候选同字号、半透明;空闲时的不透明小块只比字宽一点、与候选行同高,点小块紧左边那个字和小块正下方的字,光标落到点的位置(不弹菜单);点小块右边的页边空白(正文列以外)弹出菜单。删掉应用重装后第一次打开、候选行显示「部署中…」时,依次选「英文」「中文」:状态字和菜单的勾随即变,部署完打字是中文。
17. 长页输入延迟:准备一篇几万字的长页(例如把一段几百字、会换行的文字复制几十遍),光标放在文末和中间各试一次,英文状态连打一句、中文状态连打几个词,再上下滑动:每键到字出现没有可察觉的延迟,滑动不卡;若有延迟,记下字数与机型(模拟器上约 5 万字、光标在文末时每键约 18ms,见 ios.md §3.3「TextKit 2 的估算高度」)。
18. 切换中 / 英的快捷键(2026-11-21):设置面板「输入法」一组的「切换中 / 英」依次选「Control + 空格」「Option + 空格」「Shift + 空格」,各按一次:「中」变「英」,打 abc 直接上屏;再按回到「中」;组字中按,组字按原文上屏再切;选「系统输入法」后按,回到「中」;正文里不多出空格,不响打字音。按住不放不连切;Shift + 空格之后松开 Shift 不再切一次;选「Shift + 空格」时按着 Shift 打完大写字母再按空格,打出空格、不切(2026-11-24)。选「关」后按 Control + 空格,不切中 / 英。**重点确认系统是否先截走**:模拟器上(系统键盘为简体拼音 + English)三种组合都到了应用、都能切,「关」时 Control + 空格交给引擎、不切;但 iPadOS 接实体键盘时 Control + 空格(或地球键)可能被系统用来切换键盘,真机是否先截走未确认。若某个组合在真机上被系统截走(按了不切,或系统键盘被切了),记下机型与系统版本;若是 Control + 空格,设置里在它下面加灰字「若系统已用于切换键盘,请改选其他」,默认值不变。
19. 中英文自动空格(SUMI-261121-08):中文状态打「你好」上屏,切英文打 hello,再切中文打「世界」上屏:正文是「你好 hello 世界」;中文状态在「第」后打数字 3,成「第 3」。标点两边、已有空格后不再加;光标放在已有英文前面打中文,右边不加空格。选「系统输入法」后同样打一遍,不自动加。自动加的空格不多响一声打字音。
20. 候选行与输入行的间距(SUMI-261121-08):设置里行距拉到 1.0、1.6、2.5 各看一次:候选行上缘与光标所在行字的下缘之间的空白,和正文两行之间的空白一样大,行距大间距就大;光标在视区最后一行时候选行仍整条露出来。
21. 状态字渐隐(SUMI-261121-11,下面的 3 秒、第一次点只显示、切换后短暂显示是待确认的默认值):点正文取得焦点,状态字「中」照常显示;打一个字,约 3 秒后「中」连同它那一小块底慢慢淡去,下一行的字露出来,再打字不再出现。淡去后点原来的位置:「中」约半秒内慢慢显示出来,不弹菜单、光标不动;再点才弹菜单;菜单开着不淡,收起后约 3 秒再淡。按切换快捷键或单按左 Shift:立刻显示「英」,约 3 秒后淡去。收起或拔掉实体键盘再接上(或切到别的应用再回来):状态字先显示,打字后再淡。

## iPhone Duo 半折打字手工验收

规范 [`ios.md` §3.7](../../docs/spec/platform/ios.md#37-iphone-duo-半折打字)。只能在 iPhone Duo 真机上做。iPhone Duo 模拟器要用它专用的运行时 `com.apple.CoreSimulator.SimRuntime.iOS-27-2-iPhone19-4`(`xcodebuild -downloadPlatform iOS` 会一并装上;通用的 iOS 27.2 运行时建不了 Duo),启动后停在合上状态,App 显示在外屏;`simctl` 与 DeviceHub 都没有开合转轴的控件,半折布局在模拟器上看不到。自动测试只覆盖「何时进入半折」的纯判定(`DeskPostureTests`)。

1. 横拿、半折:正文只在折痕以上,软键盘弹在下半屏,折痕以下是底座,「···」条在底座上;
2. 半折时编辑面没有焦点:自动聚焦并弹出键盘;
3. 开合转轴、半折时转成竖拿:正文区平滑移到新位置,画面不跳;打开「减少动态效果」时直接到位;
4. 软键盘比下半屏高(如开着候选条):正文不被键盘挡住;
5. 系统拼音组字中开合转轴:组字不断,选词照常上屏;
6. 开着聚焦打字:当前行在上半屏居中,渐隐只作用于上半屏;
7. 收起键盘后正文仍在上半屏,点正文键盘再弹出;
8. 完全展开、合上(外屏)、普通 iPhone、iPad:与没有这项功能时完全一样。

以上本人 2026-11-24 在 iPhone Duo 真机验收通过(提交 50bf798)。

## TestFlight

规范 [`ios.md` §1](../../docs/spec/platform/ios.md#1-范围):第一阶段走 TestFlight 自用,不公开发行;Bundle ID、签名身份、TestFlight 配置都不进仓库。

- 前提:`Signing.local.xcconfig` 已填好;Xcode「设置 → 账户」里登录了该团队的账号(上传用它,脚本不碰密钥);App Store Connect 里已有这个 Bundle ID 的 App 记录(第一次要在网页上新建)。
- 上传:`bash apps/ios/scripts/upload-testflight.sh`。构建号用年月日时分;处理完(通常 5–15 分钟)后在 App Store Connect 的 TestFlight 页可见。
- `ITSAppUsesNonExemptEncryption` 为 `false`:应用只用系统 TLS 与 SHA-256 摘要,不再逐次回答出口合规问题。
- 内部测试组(团队成员)不用审核;公开链接只能给外部测试组,第一个构建要过 Beta 版 App 审核。
